# AI_USAGE.md

## AI Tool Used

- **Tool:** ChatGPT
- **Model:** GPT-5.6 Luna
- **Purpose:** Assistance with understanding the research paper, designing the replication pipeline, implementing neural-network architectures, debugging code, implementing SHAP-based explainability, analyzing experimental results, preparing result files, and documenting the project.

### Other Tools Used

- **Google Colab** — execution of Python/TensorFlow code, model training, evaluation, and generation of plots.
- **Python / Jupyter environment** — processing experimental results and creating CSV files and project artifacts.
- **ChatGPT Files tools** — reading and retrieving the research paper and project/reference files provided during the conversation.

> AI-generated code and suggestions were reviewed, modified, tested, and executed by the project team. The experimental results reported in the project were obtained from our own pipeline executions.

## Prompts Used

The prompts below are refined versions of the prompts used during the project. They represent the main categories of assistance requested from ChatGPT.

### 1. Understanding the paper and replication requirements

> Analyze the provided Sharma et al. (2024) paper and identify the datasets, preprocessing steps, model architectures, hyperparameters, evaluation metrics, and XAI method required to reproduce the key experiments. Clearly distinguish information explicitly specified by the paper from implementation assumptions required because details are missing.

### 2. Dataset preprocessing

> Create a reproducible preprocessing pipeline for NSL-KDD and UNSW-NB15 based on the paper. Handle categorical features, missing/infinite values, label encoding, normalization, feature selection, and train/validation/test splitting. Clearly mark any preprocessing step that is an assumption rather than explicitly specified by the paper.

### 3. DNN implementation

> Implement the DNN architecture required for the Sharma et al. (2024) replication using TensorFlow/Keras. Use the specified hidden layers, neurons, activation functions, output classes, optimizer, learning rate, regularization, dropout, and training parameters. Make the implementation reusable for both NSL-KDD and UNSW-NB15.

### 4. 1D-CNN implementation

> Implement the 1D-CNN architecture for the Sharma et al. (2024) replication using TensorFlow/Keras. Use the convolutional parameters specified by the paper and clearly identify any architecture details that are not explicitly specified. Make the model reusable for both datasets.

### 5. Debugging dataset and preprocessing errors

> Inspect the following Python traceback and determine the exact cause of the error. Provide a corrected replacement code block that preserves the intended preprocessing pipeline and does not introduce unnecessary changes.

### 6. Debugging model and training errors

> Inspect this TensorFlow/Python error and identify which variable, model, or preceding code block is missing. Provide the exact code block that should be run or replaced so that the existing experiment pipeline can continue without changing its intended architecture.

### 7. Evaluation and metrics

> Evaluate the trained models on the test sets and calculate accuracy, macro precision, macro recall, macro F1, weighted precision, weighted recall, weighted F1, confusion matrices, and training time. Save the results in a consistent CSV format across all models and datasets.

### 8. Training visualization

> Generate training and validation loss and accuracy curves for each dataset/model combination, along with confusion matrices using the appropriate class labels. Save the plots so they can be included in the replication report.

### 9. SHAP/XAI implementation

> Implement SHAP-based explainability for the trained intrusion-detection model. Calculate SHAP values on a representative sample and generate a SHAP summary/beeswarm plot showing the global importance and direction of feature contributions. Use the actual feature names and explain what the SHAP values represent.

### 10. Result verification

> Compare the results obtained from our pipeline with the accuracy values reported in the original paper. Do not replace our experimental results with values from the paper or values provided in the prompt. Use the actual metrics produced by our executed pipeline and calculate the difference from the paper's reported results.

### 11. Result file preparation

> Create a clean CSV containing only the requested datasets and models. Remove unnecessary columns such as experiment IDs and training execution time when requested. Use the numerical results generated by our pipeline rather than values copied from an example table.

### 12. Architecture documentation

> Extract the model architectures used in our actual replication pipeline and provide them as standalone Python files containing the model construction code and relevant hyperparameters. Clearly distinguish documented paper specifications from assumptions made during reconstruction.

## How AI Output Was Modified

AI-generated output was **not used blindly**. The project team reviewed, tested, corrected, and adapted the generated code before using it in the experiments.

### 1. Dataset paths were adapted

The generated code initially assumed a particular directory structure. It was modified to match the actual files available in Google Colab, including:

- `KDDTrain+.txt`
- `KDDTest+.txt`
- `UNSW_NB15_training-set.csv`
- `UNSW_NB15_testing-set.csv`

### 2. Dataset preprocessing was corrected

The UNSW-NB15 label preprocessing was modified after an execution error caused by inconsistent capitalization of `attack_cat` values.

The labels were normalized to lowercase and explicitly mapped to:

- `normal`
- `generic`
- `exploits`
- `dos`
- `fuzzers`

The preprocessing was also adapted to the actual feature columns available in the downloaded datasets.

### 3. Model implementation was debugged

Several generated code blocks were modified after execution errors, including:

- undefined dataset variables;
- undefined model variables;
- feature-count mismatches; and
- label encoding issues.

The corrected code was executed in Google Colab before the final experimental results were recorded.

### 4. Architecture details were checked against the paper

The generated DNN and 1D-CNN architectures were compared with the available paper information.

Where the paper did not provide sufficient implementation details, the corresponding choices were documented as assumptions rather than being presented as the authors' exact implementation.

### 5. Experimental results were taken from actual executions

The final accuracy, precision, recall, and F1 values were taken from the actual output of the executed pipelines.

Values from example tables or values reported by the original paper were not substituted for our experimental results.

### 6. SHAP implementation was executed

SHAP was implemented for model explainability and executed on the trained model. SHAP values were calculated for a representative sample and a SHAP summary/beeswarm plot was generated using the feature names from the dataset.

### 7. Result files were cleaned

The generated result files were modified to retain only the required datasets, models, and evaluation metrics.

Unnecessary fields such as:

- experiment IDs;
- training execution time; and
- redundant columns

were removed when preparing the final comparison files.

### 8. Architecture files were separated

The model architectures were separated from the larger training notebooks into standalone Python files:

- `dnn_architecture.py`
- `1d_cnn_architecture.py`

This was done to make the model implementations easier to inspect and reproduce.

### 9. Assumptions were documented

Where the original paper did not provide enough implementation detail, assumptions were explicitly documented instead of presenting them as the authors' original implementation.

In particular, details of the 1D-CNN architecture that were not explicitly specified in the paper were treated as reconstruction assumptions.

## Role of AI in the Project

AI was used as an **assistance and development tool** for:

- understanding the research paper;
- generating initial implementations;
- debugging errors;
- suggesting preprocessing procedures;
- generating evaluation and visualization code;
- implementing SHAP explanations;
- organizing experimental results; and
- preparing documentation.

The project team was responsible for:

- reviewing the generated code;
- verifying the implementation against the research paper;
- executing the experiments;
- correcting implementation errors;
- identifying and documenting assumptions;
- checking the experimental results; and
- preparing the final submission.

AI-generated suggestions that were inconsistent with the paper or actual experimental setup were corrected or discarded before inclusion in the final project.
